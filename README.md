# AI Product Content Generator

Локальный MVP AI-помощника для подготовки черновиков товарных карточек контрольно-измерительных приборов для B2B-интернет-магазина.

Сервис принимает данные о товаре в JSON, нормализует их и передаёт в языковую модель через OpenRouter API. В результате формируется структурированная карточка с SEO-контентом и коммерческим блоком.

## Возможности

- REST API на FastAPI для генерации товарной карточки.
- Приём входных данных в формате JSON из разных источников.
- Нормализация данных товара к единой внутренней структуре.
- Генерация SEO-заголовка длиной до 70 символов.
- Генерация SEO-описания с целевым объёмом 800-1200 символов.
- Формирование структурированного списка ключевых характеристик.
- Генерация 3–5 поисковых запросов.
- Формирование коммерческого блока для менеджера.
- Предупреждения о недостатке исходных данных.
- Проверка структуры и обязательных полей ответа с помощью Pydantic.
- Повторные попытки генерации при временных ошибках LLM и некорректном формате ответа.

Технические характеристики в итоговой карточке берутся непосредственно из нормализованных входных данных, а не генерируются языковой моделью.

## Запуск

Требуется Python 3.11 или выше и API-ключ OpenRouter.

### 1. Клонирование репозитория

```bash
git clone https://github.com/feodotevdima/ai-product-generator
cd ai-product-generator
```

### 2. Создание виртуального окружения

```bash
# macOS / Linux
python3 -m venv .venv

# Windows PowerShell
python -m venv .venv
```

Активация:

```bash
# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1
```

### 3. Установка зависимостей

```bash
pip install .
```

### 4. Настройка переменных окружения

Создайте файл `.env` в корне проекта:

```env
OPENROUTER_API_KEY=your_api_key
OPENROUTER_MODEL=your_model
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
MAX_ATTEMPTS=3
```

Укажите действующий API-ключ OpenRouter и название используемой модели.
В ходе разработки и тестирования сервиса использовалась модель nvidia/nemotron-3.5-super-vl:free

### 5. Запуск сервера

```bash
uvicorn main:app --app-dir src --reload
```

После запуска:

- API: http://127.0.0.1:8000
- Swagger UI: http://127.0.0.1:8000/docs

## API

Генерация карточки выполняется через endpoint:

`POST /api/product-cards/generate`

Пример запроса:

```bash
curl -X POST http://127.0.0.1:8000/api/product-cards/generate \
  -H 'accept: */*' \
  -H "Content-Type: application/json" \
  -d @data/product_1.json
```

Пример входных данных:

```json
{
  "name": "E40S6-5000-3-N-5",
  "manufacturer": "Autonics",
  "description": "Энкодер инкрементальный с выступающим валом диаметром 6 мм (диаметр корпуса 40 мм)",
  "specs": {
    "Диаметр вала": "6 мм",
    "Диаметр корпуса": "40 мм"
  }
}
```

Фактическая структура входных данных может отличаться: перед передачей в сервис данные нормализуются к единому формату.

## Промпт и принятые решения

Системный промпт находится в `core/prompts.py`. Он задаёт модели правила формирования товарной карточки и требования к результату:

- Использовать только сведения из входных данных.
- Не придумывать технические характеристики, числовые значения, материалы, стандарты, комплектацию и сертификаты.
- Не добавлять неподтверждённые области применения, преимущества и совместимость.
- Формировать SEO-заголовок длиной не более 70 символов.
- Стремиться к объёму SEO-описания 800–1200 символов.
- Возвращать от 3 до 5 поисковых запросов.
- Указывать предупреждения, если исходных данных недостаточно.
- Возвращать результат в заданной JSON-структуре.

Защита от выдумывания характеристик реализована не только на уровне промпта. Поле `key_characteristics` формируется приложением непосредственно из `specs` исходного товара. Таким образом, модель не может самостоятельно добавить или изменить технические значения в этом блоке.

Для проверки структуры ответа используется Pydantic-модель `ProductCard`. Она контролирует обязательные поля, длину SEO-заголовка, количество поисковых запросов и отсутствие пустых значений.

Если исходных данных недостаточно для содержательного SEO-описания, предпочтительнее вернуть более короткий текст с предупреждением, чем дополнять его неподтверждёнными сведениями.

Для взаимодействия с LLM используется OpenRouter API через асинхронный OpenAI SDK. API-ключ и параметры модели передаются через переменные окружения.

## Примеры результатов

В каталоге data/ находятся входные JSON-файлы двух предоставленных товаров. В подкаталоге data/results/ сохранены соответствующие результаты генерации товарных карточек.

## Ограничения

- Качество SEO-текста зависит от полноты и достоверности входных данных.
- При недостатке информации невозможно гарантировать целевой объём SEO-описания без риска добавления неподтверждённых сведений.
- Автоматическая проверка технической достоверности исходных данных по паспортам и каталогам производителей не выполняется.
- Противоречия между текстовым описанием и характеристиками автоматически не выявляются.
- Нормализация входных данных зависит от поддерживаемых форматов источников.
- Результат генерации является черновиком и требует проверки специалистом перед публикацией.

## Возможные улучшения

1. Добавить тесты для нормализации входных данных, генерации карточек и обработки ошибок.
2. Расширить поддержку форматов входных данных из различных товарных каталогов.
3. Добавить автоматическое выявление противоречий между характеристиками и описанием.
4. Разработать веб-интерфейс для ввода данных о товаре, запуска генерации и просмотра результата с возможностью копирования.
